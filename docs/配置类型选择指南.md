# NeoForge 配置类型选择指南

## 概述

NeoForge 配置系统提供了三种配置类型：COMMON（通用）、SERVER（服务器）和
CLIENT（客户端）。正确选择配置类型对于确保模组的功能正常、数据同步和用户体验至关重要。

## 配置类型详解

### 1. COMMON（通用配置）

#### 定义

通用配置是客户端和服务器共享的配置，存在于客户端和服务器两端，但由服务器控制。

#### 特性

- 配置文件：`modid-common.toml`
- 存在位置：客户端和服务器
- 控制权：服务器（客户端无法修改）
- 同步：服务器到客户端（服务器配置会同步到客户端）

#### 适用场景

1. **游戏机制参数**：影响游戏核心玩法但需要在客户端显示的参数
   ```java
   // 示例：村庄生成距离
   public static final ModConfigSpec.IntValue villageGenerationDistance;
   ```

2. **功能开关**：控制模组功能的启用/禁用状态
   ```java
   // 示例：是否启用自定义村庄生成
   public static final ModConfigSpec.BooleanValue enableCustomVillageGeneration;
   ```

3. **共享常量**：需要在客户端和服务器保持一致的常量值
   ```java
   // 示例：最大村庄数量
   public static final ModConfigSpec.IntValue maxVillagesPerWorld;
   ```

4. **调试选项**：影响客户端和服务器行为的调试设置
   ```java
   // 示例：调试模式开关
   public static final ModConfigSpec.BooleanValue enableDebugMode;
   ```

#### 使用注意事项

- 服务器端修改会同步到所有连接的客户端
- 客户端无法修改通用配置
- 修改后需要重启服务器才能生效

### 2. SERVER（服务器配置）

#### 定义

服务器配置仅存在于服务器端，客户端完全不可见。

#### 特性

- 配置文件：`modid-server.toml`
- 存在位置：仅服务器
- 控制权：服务器管理员
- 同步：无（客户端无法访问）

#### 适用场景

1. **服务器管理设置**：仅影响服务器运行的参数
   ```java
   // 示例：每个村庄的最大村民数量
   public static final ModConfigSpec.IntValue maxVillagersPerVillage;
   ```

2. **性能优化参数**：控制服务器性能的设置
   ```java
   // 示例：村庄生成线程池大小
   public static final ModConfigSpec.IntValue villageGenerationThreadPoolSize;
   ```

3. **安全相关设置**：影响服务器安全的配置
   ```java
   // 示例：是否允许玩家破坏村庄结构
   public static final ModConfigSpec.BooleanValue allowVillageDestruction;
   ```

4. **数据存储设置**：控制服务器数据存储的参数
   ```java
   // 示例：村庄数据自动保存间隔（分钟）
   public static final ModConfigSpec.IntValue villageDataSaveInterval;
   ```

5. **权限控制**：管理玩家权限的设置
   ```java
   // 示例：哪些玩家可以管理村庄
   public static final ModConfigSpec.ConfigValue<List<? extends String>> villageAdmins;
   ```

#### 使用注意事项

- 客户端完全无法访问这些配置
- 修改后需要重启服务器才能生效
- 适合存储敏感的服务器管理信息

### 3. CLIENT（客户端配置）

#### 定义

客户端配置仅存在于客户端，服务器端不可见。

#### 特性

- 配置文件：`modid-client.toml`
- 存在位置：仅客户端
- 控制权：玩家
- 同步：无（服务器无法访问）

#### 适用场景

1. **视觉效果设置**：控制客户端渲染效果的参数
   ```java
   // 示例：村庄高亮颜色
   public static final ModConfigSpec.ConfigValue<String> villageHighlightColor;
   ```

2. **UI显示选项**：控制用户界面显示的设置
   ```java
   // 示例：是否显示村庄信息HUD
   public static final ModConfigSpec.BooleanValue showVillageInfoHUD;
   ```

3. **音频设置**：控制客户端音效的参数
   ```java
   // 示例：村庄音效音量
   public static final ModConfigSpec.DoubleValue villageSoundVolume;
   ```

4. **输入控制**：控制键盘/鼠标输入的设置
   ```java
   // 示例：村庄信息快捷键
   public static final ModConfigSpec.ConfigValue<String> villageInfoKeybind;
   ```

5. **性能优化选项**：控制客户端渲染性能的设置
   ```java
   // 示例：村庄渲染距离
   public static final ModConfigSpec.IntValue villageRenderDistance;
   ```

6. **个性化设置**：允许玩家自定义的选项
   ```java
   // 示例：村庄名称显示格式
   public static final ModConfigSpec.ConfigValue<String> villageNameDisplayFormat;
   ```

#### 使用注意事项

- 服务器无法访问这些配置
- 修改后通常只需要重新加载资源或重启客户端
- 不同玩家的客户端配置可能不同

## 常见配置类型选择示例

### 示例1：村庄生成开关

```java
// 应该使用COMMON，因为：
// 1. 影响服务器端逻辑（村庄生成）
// 2. 客户端需要知道是否显示相关UI元素
// 3. 需要由服务器管理员控制
public static final ModConfigSpec.BooleanValue enableVillageGeneration;
```

### 示例2：村庄高亮颜色

```java
// 应该使用CLIENT，因为：
// 1. 仅影响客户端视觉效果
// 2. 不同玩家可能有不同偏好
// 3. 服务器不需要知道这个设置
public static final ModConfigSpec.ConfigValue<String> villageHighlightColor;
```

### 示例3：最大村庄数量

```java
// 应该使用SERVER，因为：
// 1. 仅影响服务器端逻辑和性能
// 2. 客户端不需要知道这个限制
// 3. 属于服务器管理设置
public static final ModConfigSpec.IntValue maxVillagesPerWorld;
```

### 示例4：村庄信息显示格式

```java
// 应该使用CLIENT，因为：
// 1. 仅影响客户端UI显示
// 2. 不同玩家可能有不同偏好
// 3. 服务器不需要控制显示格式
public static final ModConfigSpec.ConfigValue<String> villageInfoDisplayFormat;
```

## 特殊情况处理

### 1. 配置依赖

如果某个配置依赖于另一个配置，确保它们使用相同的配置类型，或者依赖关系是单向的（例如，CLIENT配置可以依赖COMMON配置，但COMMON配置不能依赖CLIENT配置）。

### 2. 配置迁移

在模组更新过程中，如果需要将配置从一个类型迁移到另一个类型：

- 提供迁移指南
- 在代码中处理旧配置的兼容性
- 添加适当的警告和日志

### 3. 配置验证

不同类型的配置可能需要不同的验证规则：

- SERVER配置：更严格的服务器端验证
- CLIENT配置：考虑客户端性能影响
- COMMON配置：兼顾服务器和客户端的验证需求

## 最佳实践总结

1. **明确配置的用途和影响范围**：在创建配置前，明确它会影响哪些组件，谁需要控制它。

2. **优先选择最受限的配置类型**：如果配置可以在CLIENT中实现，就不要使用COMMON；如果可以在SERVER中实现，就不要使用COMMON。

3. **考虑多玩家环境**：在多人游戏中，不同玩家的客户端配置可能不同，但服务器配置必须一致。

4. **提供清晰的配置注释**：在配置文件中提供清晰的注释，说明每个配置的用途和影响。

5. **测试配置变更**：确保配置变更能够正确应用，不会导致游戏崩溃或不一致状态。

6. **考虑性能影响**：某些配置可能会影响性能，特别是CLIENT配置，需要提供合理的默认值和范围限制。
