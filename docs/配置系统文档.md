# VillageGenesis 配置系统文档

## 概述

VillageGenesis 使用 NeoForge
的配置系统，提供了一个简洁、高效的配置管理方案。该系统支持三种类型的配置：通用配置（COMMON）、服务器配置（SERVER）和客户端配置（CLIENT）。

## 系统架构

### 核心组件

1. **配置类**：
    - `CommonConfig` - 通用配置类，包含客户端和服务器共享的配置项
    - `ServerConfig` - 服务器配置类，包含仅服务器端使用的配置项
    - `ClientConfig` - 客户端配置类，包含仅客户端使用的配置项

2. **事件监听器**：
    - `ConfigEventListeners` - 配置事件监听器，处理配置加载和重载事件

3. **工具类**：
    - `ConfigUtils` - 配置工具类，提供创建各种类型配置项的辅助方法

## 配置系统特点

1. **极简设计**：配置系统只保留最核心的功能，没有不必要的复杂性
2. **直接访问**：配置值通过静态字段直接访问，无需通过中间层
3. **事件解耦**：配置事件监听完全独立，各模块可根据需要自行监听
4. **符合 NeoForge 理念**：完全遵循 NeoForge 配置系统的设计原则

## 使用方法

### 1. 注册配置

在主类构造函数中注册配置：

```java
public VillageGenesis(IEventBus modEventBus, ModContainer modContainer) {
    // 注册配置文件到ModContainer
    modContainer.registerConfig(ModConfig.Type.COMMON, CommonConfig.SPEC);
    modContainer.registerConfig(ModConfig.Type.SERVER, ServerConfig.SPEC);
    modContainer.registerConfig(ModConfig.Type.CLIENT, ClientConfig.SPEC);

    // 其他初始化代码...
}
```

### 2. 访问配置值

直接通过配置类的静态字段访问配置值：

```java
// 获取布尔值配置
boolean debugMode = CommonConfig.enableDebugMode.get();

// 获取整数配置
int maxVillagers = ServerConfig.maxVillagersPerVillage.get();

// 获取字符串配置
String highlightColor = ClientConfig.villageHighlightColor.get();
```

### 3. 监听配置变更

使用 `@SubscribeEvent` 注解监听配置变更事件：

```java

@EventBusSubscriber(modid = VillageGenesis.MOD_ID)
public class MyConfigListener {

    @SubscribeEvent
    public static void onConfigChanged(ModConfigEvent event) {
        // 处理配置变更
        if (event.getConfig().getType() == ModConfig.Type.SERVER) {
            // 服务器配置变更处理
        }
    }
}
```

### 4. 创建配置项

使用 `ConfigUtils` 工具类创建各种类型的配置项：

```java
public static ModConfigSpec.BooleanValue enableDebugMode;
public static ModConfigSpec.IntValue maxVillagersPerVillage;
public static ModConfigSpec.ConfigValue<String> villageHighlightColor;

static {
    ModConfigSpec.Builder builder = new ModConfigSpec.Builder();

    // 创建布尔值配置项
    enableDebugMode = ConfigUtils.defineBoolean(builder, "enableDebugMode", false,
            "是否启用调试模式");

    // 创建整数配置项（带范围限制）
    maxVillagersPerVillage = ConfigUtils.defineInt(builder, "maxVillagersPerVillage",
            10, 1, 100, "每个村庄的最大村民数量");

    // 创建字符串配置项
    villageHighlightColor = ConfigUtils.defineString(builder, "villageHighlightColor",
            "#FF0000", "村庄高亮颜色");

    SPEC = builder.build();
}
```

## 配置文件位置

配置文件存储在 Minecraft 服务器的 `config` 目录下：

- `village_genesis-common.toml` - 通用配置文件
- `village_genesis-server.toml` - 服务器配置文件
- `village_genesis-client.toml` - 客户端配置文件

## 最佳实践

1. **配置分类**：根据配置项的用途正确选择配置类型（COMMON、SERVER、CLIENT）
2. **默认值**：为所有配置项提供合理的默认值
3. **注释**：为每个配置项提供清晰的注释，说明其用途和影响
4. **验证**：对配置值进行适当的验证，确保其在有效范围内
5. **事件处理**：在配置变更事件中更新相关的游戏状态

## 注意事项

1. 配置值访问是线程安全的，可以在任何地方安全访问
2. 配置变更事件会在配置文件重新加载时触发
3. 服务器配置在客户端不可见，客户端配置在服务器端无效
4. 通用配置在客户端和服务器端都可用，但修改需要服务器重启

## 扩展配置系统

如需添加新的配置项：

1. 在相应的配置类中添加新的配置字段
2. 在静态初始化块中使用 `ConfigUtils` 创建配置项
3. 在代码中通过静态字段访问配置值
4. 如需响应配置变更，添加相应的事件监听器

## 故障排除

1. **配置未生效**：检查配置文件是否正确生成，配置项名称是否匹配
2. **配置值异常**：检查配置值的类型和范围是否符合要求
3. **事件未触发**：确保事件监听器类有 `@EventBusSubscriber` 注解，方法有 `@SubscribeEvent` 注解
